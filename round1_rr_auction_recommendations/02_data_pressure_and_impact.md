# Stage 02 — Transform the pack and validate pressure and impact

## Data transformations

1. Keep the raw files immutable. Use canonical numeric IDs with explicit crosswalks, validated join cardinality and delivery order. Reconcile delivery, fixture, innings, player, XI and franchise grains. Audit role sources, Impact Player entries, duplicate or conflicting IDs, exclusions, competition/season dates, zero exposure and missingness. Treat a missing opponent or venue cell as missing evidence. Use vectorized grouping and cache the cleaned ledger with a verified schema.
2. Profile the supplied contextual fields by competition, season, venue and role. Distinguish static or strictly prior information from events observed on the ball. Batting hand, prior role, bowling type and opponent strength can be useful. Current-ball stroke, variation, speed, runs, and dismissal are outcome or diagnostic fields. Build lagged player tendencies from past opportunities if they add value. Bowl speed includes 77,861 literal zero entries. Inspect units, flag invalid observations, and use measured speed only in a supported sensitivity. Treat sparsely covered venue or matchup cells with pooling.
3. Reuse the corrected legal-ball and terminal-state paths. Check target reached, all out, overs exhausted, tied regulation score, legal count on wides/no-balls, carryover free hit, byes/leg-byes and penalties, credit on stumping and run-out, and striker versus nonstriker dismissal. Verify legal-ball denominator versus runs or wickets attributed to extra events. Verify that including a legitimate extra event in the numerator has the corresponding expectation definition. Use compact hand-built edge cases for tests and observed deliveries for training.
4. Save provenance for targets and special rules. Latest run coverage has six independently verified chase targets and 800 reconstructed ones. Audit representative close chases and known exceptions from public scorecards keyed to the supplied match IDs. Compare corrected labels with reconstruction-based labels in supported cases. Keep known, proxy and unresolved states distinguishable. Use bounded sensitivity grounded in the checked scorecard discrepancies, and report when a near-cutoff player's rank depends on proxy states.

## Pressure and value

5. Preserve a comparable base pressure definition. Estimate pre-ball win-value sensitivity from plausible next outcomes at a known state, with exact terminal outcomes and a documented tie value. Fit transition and state distributions from prior data. For first innings include resource loss and setting-total stress. For chases include required rate, wickets, balls, score gap and closeness. Validate that a routine death over, a close chase, a wickets-in-hand collapse and an almost decided match can behave differently. Keep P80 as a reportable reference and P75/P85 as sensitivities. Compare one continuous pressure variant, using leverage and resource/required-rate stress as distinct features with documented scaling and a small tuning grid.
6. Measure runs and wicket contribution against comparable roles and conditions. For batting start with (actual batter runs minus expected runs) minus wicket value times (striker dismissal indicator minus expected dismissal risk). For bowling start with (expected bowler-charged runs minus actual charged runs) plus wicket value times (credited wicket indicator minus expected credited wicket risk). Fit expected values and wicket value from earlier matches. Verify signs and opportunity weights. Aggregate per 12 legal balls for ordinary and pressure opportunities, and preserve counts of legal balls, deliveries and matches. Report observed impact and a forecast as distinct columns.
7. Create phase- and match-level analysis tables. Include innings, powerplay/middle/death, position or overs usage, opposition band, supported pace/spin matchup, recent versus prior windows, IPL/T20I/emerging, phase-specific evidence, and short versus long stints. Use historical phase definitions consistently and check changes in league scoring environment. For usual-versus-pressure comparison, use a feasible common deployment mix and compare within supported strata. Label unsupported player-role-context combinations. Include a simple run rate/strike rate or economy/wickets view as an interpretation check.
8. Run exploratory checks before fitting. Show effective evidence by domain and role, pressure exposure concentration by match, recency gaps, correlation among related metrics, and sample counts at every exclusion. Repeat examples under ordinary, pressure and altered threshold definitions. Save two ledger examples with exact arithmetic and source provenance. Recheck that adding future outcomes, team changes or rows leaves earlier features and thresholds unchanged.

## Loop

On a cricket-state, key or attribution failure, fix the earliest transformation and regenerate pressure labels and impact aggregates. If an EDA field is unreliable or temporally unavailable, revise the feature contract and reprofile. If alternative pressure definitions change who is evaluated, retain a common primary target for model comparisons and report label sensitivity independently.
