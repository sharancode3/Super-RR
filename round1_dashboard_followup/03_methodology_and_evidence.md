## Agent prompt

Build a distinct, linked **Methodology** section with its own heading and a stable anchor. Use the existing page and routing structure. Keep an informative summary immediately visible, followed by technical detail that expands on demand. The evaluator should understand why the ranking exists, follow a real delivery to a scored player, and see what changed when RR's constraints were applied.

Mention the free-hit frequency adjustment and first-innings resource-stress term where explaining full implementation. The main cutoff is a historical 80th percentile by innings and competition tier. Use one actual example. ### UI and data implementation

- Use a compact narrative by default, with a stage timeline, pre-ball example, grouped backtest comparison and a ranking-change visual. Draw a small custom SVG only where it clarifies a relationship, for example connects the scoring and selection steps. Keep charts and formulas readable with text equivalents, correct units and simple accessible controls. Compute each figure from the same data passed to the textual summary. Use no emojis in headings, labels or tooltips.
- Share display formatters and data with the athlete boards. A bundle field may be sourced, auditable derived, or clearly described illustrative copy. Keep timeline copy separate from generated metrics and store each fact source. Strip hardcoded legacy numbers from live components, page metadata, generated HTML and documentation used as evidence. Use a native disclosure for technical details where feasible.
- Keep scoped navigation for the chapter. With the keyboard and at small widths, all evidence and headings are reachable without depending on a tab's hidden state. Stabilize anchor navigation. Ensure the opening reading path fits a normal judging session.
