# R02 · Repair reliability and fit parity

**End goal** The chosen reliability score must reflect the player's actual fitted support and uncertainty. Assessment and production must score the same quantity.

```text
Read round1_release_review/03_model_evidence_parity.md and inspect rr_pressure/challengers.py, compare.py, forecast.py and rankings.py. Preserve the corrected diagnostic behavior from R00. Implement the shared fit, predict and rank contract before trying to pick winners.

Loop: reproduce support mismatch -> fit with a declared statistical target -> test ranking parity -> inspect hard cases.

1. Freeze the target. On each eligible event, let w be the past-estimated run cost of a wicket in that state. For batting use (bat runs - expected bat runs) - w * (striker dismissal - expected dismissal). For bowling use (expected bowler charges - actual charges) + w * (credited wicket - expected credited wicket). Use verified charges or the labelled proxy. Define the match label as 12 * eligible pressure impact / eligible pressure legal balls. Document how non-legal events enter the numerator and the exact cohort used. A normalized rate and an actual 12-ball episode are different quantities. Specify cutoff, role, phase/tier context, target support, cold-start policy and weights. Store one row per assessment key and candidate with pre-match input, fit ID and realized label recorded separately. Every consumer must use the same ranking and tie-break function. Candidates without their own assessment and release predictions remain diagnostic.
2. Preserve B0 for ordinary performance and B1 for shrunk player pressure effects. Estimate pressure-versus-usual in comparable role/phase/tier states and report overlap. One acceptable starting estimator shrinks the player's pressure effect toward its role/tier prior by n_eff / (n_eff + k), with k learned only on earlier data. Calculate n_eff from independent match weights, for example (sum w_i)^2 / sum(w_i^2), where w_i are match weights distinct from wicket cost. For D, fit partially pooled location and residual scale on earlier match clusters. Use a Student-t likelihood or robust shrinkage if tails justify it. Include player-estimate uncertainty in a predictive distribution and verify how the model behaves with limited support. An equal-match mean with a balls-based shrinkage count needs justification or replacement. Compare with a simple regularized version before adding model complexity.
3. Derive a calibrated Q25 for the declared IPL context or a clearly supported rate. Use the same predictive distribution for other quantiles. Use coverage checks and avoid implying that Q25 penalizes thin support if the subtraction is identical for all players. Keep model-fit pressure balls and matches separate from overall exposure, and test that small samples shrink or widen uncertainty under the fitted method. Verify the D case where nine overall fixtures were three in the fit. Never multiply or change a player's score by hand.
4. Test all selectable branches at validation, retrospective and release cutoffs. A/C, B0/B1 and the challengers must dispatch explicitly. Unknown model IDs fail clearly. Compare exact keys, target values, feature sets, cold-start fallback, tie-break and selected-list IDs. A quantile-only model exports its supported quantiles. A prediction interval, player-effect interval, and resampled rank range have separate fields.
5. Define the primary list score before the fit. Use a calibrated pressure-outcome score in an explicitly specified IPL context where support permits. Preserve a separate comparison to usual performance and display it even if a B0-type model wins. Describe how historical context and any role weights affect the estimand. Keep roster and auction availability out of the statistical model. Treat any RR-specific role-weighted view as a declared scenario with its own ID and label.

Gate: contract tests exercise every selectable fit, thin samples have an evidenced treatment, score and support derive from the same record, and no candidate sees realized workload at forecast time.

PASS -> round1_rank_validation/03_select_models.md
FAIL -> repeat R02 for fit and dispatch. Redirect chronology or target data defects to round1_rank_validation/01_pressure_and_time.md.
BLOCKED -> STOP_BLOCKED with the missing fit, sample support or required prediction record. Resume at round1_rank_validation/02_fit_contract.md.
```
