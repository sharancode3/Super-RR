# R04 · Stress test ranks and verify the evidence

**End goal** Demonstrate which ranking decisions are robust, identify weak spots, and trace every stated fact to real data.

```text
Read the R03 frozen decision and the three-output contract in round1_prompts/rules_contract.md. Use the same fit interface, historical cutoff and tie-break for every perturbation and ranking export. Compare Suryakumar, Rajapaksa and Sooryavanshi as contrasting evidence cases alongside other established and sparse players, reserves and finalists near the cutoff.

Loop: reproduce the exact ranked baseline -> vary one factor -> refit and rerank -> trace claims -> independently verify.

1. Reproduce final baseline scores and order before any stress test. Refit the selected model inside each whole-match bootstrap replicate, preserving multiplicities. Track top-ten inclusion, rank intervals, eligibility loss and rank changes near the cutoff. Run leave-one-whole-match-out. Show both the effect on a fixed pool and the effect after reapplying the eligibility floor. Quantify how much evidence each top pick gets from the most influential match. Clearly label any approximate sensitivity.
2. Compare pooled, IPL-only and supported partial-pooling fits on identical later IPL keys using the selected family. Separate no IPL support from low IPL support and measure which contexts transfer. Perturb pressure thresholds or weights by rebuilding affected labels, with one change per comparison. Report actual differences and uncertainty. Use an explicit scenario or mixture distribution for phase weights and keep the predeclared base ranking separate from sensitivity variants.
3. Build cards for all 20 picks and near-cutoff reserves. Show fit ID, actual fitted exposure, usual level, matched pressure outcome and change, Q25, supported phases and opponents, IPL evidence, uncertainty and what could change the recommendation. Join canonical player ID and match ID to real fixtures and delivery rows. Generate names, dates, teams, scoring components and units from those records. Record source, date and observed/estimated/conditional status for every material claim. If evidence is missing, report unknown or omit the claim. Avoid projecting a highlight, award, or commentator's description onto the whole sample.
4. Make the auction notes actionable for RR. Build a dated roster and measured role coverage map from official RR/IPL records and available match data. For each candidate identify a concrete deployment scenario, a named incumbent or comparable alternative, and the supported edge or trade-off. Examples of contexts are powerplay opening, middle-overs recovery, death finishing, new-ball wickets, middle-overs control and death bowling. Support any claim about a roster gap with available evidence or mark it conditional. Separate rr_roster_status with its effective season, auction_status_2027 with an official evidence reference or UNKNOWN, and rr_action such as incumbent benchmark, scout if available, or verified auction option. Replace the rank-derived AUCTION_POOL_TARGET/CONTINGENCY_RESERVE availability values. A verified 2026 RR incumbent can be a keep-or-benchmark case in the RR notes while retaining its performance rank. Use exact 2027 roster and availability facts only when verified.
5. Reconcile the terminal, shortlist, report-ready evidence and form checklist by ID, role and order. Form rank is derived from the same score order over the verified role pool, with exclusion reasons and separate performance ranks. Unknown or incomplete options cannot certify a complete list. Test that changing the 2027 availability status changes only the auction notes, and changing the role-specific form eligibility changes only the form mapping. Verify all rows programmatically, hand-check one real batting and bowling replay, and reject the handoff's Rajapaksa ID and unrelated fixture without encoding a preferred rank.

Gate: all ranks and evidence are tied to the selected model, robustness uses that model, actual fixtures and figures reconcile, and each pick has a sourced or explicitly conditional RR use case. Statistical rank, form mapping, and 2027 availability are independently verifiable.

PASS -> round1_rank_validation/05_review_gate.md
FAIL -> repeat R04 for stability and evidence mismatches. Send score and ID-join bugs to round1_rank_validation/02_fit_contract.md, league/pressure data issues to round1_rank_validation/01_pressure_and_time.md, and any justified protocol revision to round1_rank_validation/03_select_models.md.
BLOCKED -> STOP_PROVISIONAL if required evidence is unavailable. Resume at round1_rank_validation/04_rank_evidence.md. Pending form eligibility alone can proceed to R05 as provisional.
```
