# Round 1 validation audit

## Decision

The existing run is a prototype with genuine model fits and computed player rankings. Its saved comparison, replay evidence, and eligibility export need repair before the rankings are ready for entrant review. The active recovery route starts at [the recovery gate](round1_prompts/recovery_gate.md). It precedes the old checkpoint's Stage 11 resume instruction.

## Independently verified

- All seven raw-pack files match the recorded SHA-256 hashes. The six supplied CSVs remain the only population for training and ranking. Preserve the raw pack, the existing `artifacts` and `test_artifacts` directories, and the old checkpoint as evidence.
- All seven outputs listed in the legacy run manifest matched byte-for-byte across the two run directories. This confirms reproducibility for those files. It also reproduces the fixed claims and the validation defects below.
- The existing suite ran successfully with 48 tests passing. Some tests check that files exist, that Candidate B is selected, or that an example has a provenance field. Those assertions can pass with a fixed winner or an incorrect replay. Replace outcome-prescribing assertions with checks that can fail on the defects below.
- The implementation fits logistic regression, ridge regression, and histogram gradient boosting. The player forecast computes role priors and player estimates from recorded impacts with fixed shrinkage strengths. Deterministic results from a seeded fit are expected. Fixed claims, fixed model choices, and metrics that do not follow the input are separate issues. [Match-state training](rr_pressure/models.py) · [Player forecasts](rr_pressure/forecast.py)

## What a corrected result must prove

1. Raw inputs retain their fingerprints. Build derived copies in a new run directory with row and match provenance. Use official records only to corroborate or align the supplied matches. Keep synthetic arithmetic fixtures outside training and evaluation.
2. Real match examples reconcile independently, and ambiguous extras, states and eligibility are labeled. Test that earlier features and fitted parameters stay unchanged if a later outcome changes. Test that genuine changes to earlier training outcomes can change fitted predictions and that changed model artifacts propagate into the terminal and exports.
3. Compare candidates on the same frozen opportunities, target and workload. Report coverage separately. Include a fitted forecast without player-specific pressure effects. If the pressure interaction has weak predictive evidence, report that and keep the descriptive pressure comparison distinct from the forecast.
4. Select from measured validation and use the same trained method for refit and final rank. Report quantile calibration, uncertainty and exposure alongside top-ten results. The old 2026 results are already visible. Do not describe a repair rerun as an untouched final test. [Quantile forecast evaluation](https://doi.org/10.1146/annurev-statistics-032921-020240)
5. Generate console, evidence and CSVs from the fitted run. Verify source rows, full-precision calculations, role-specific eligibility and one snapshot. Keep unverified labels blank and reasons explicit. The entrant reviews the actual evidence before owning the final picks and rationale.
