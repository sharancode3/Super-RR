# Stage 06 · Final review and local handoff

## Agent prompt

Run two independent acceptance passes on the production build. Use the frozen ranking and the evidence reviewed in previous stages. Test the evaluator experience on the actual dashboard with its real assets.

### Pass 1 · Reproduce and audit the evidence

- Start from a fresh build output. Run the data exporter, automated data tests, type checks, component checks and production build. Build with the dependency lock file. Confirm the model code and raw input hashes are unchanged from the initial dashboard checkpoint.
- Compare both ordered lists against Stage 03 and the canonical CSV. Prove exactly 20 entries, 10 each, 19 identities, IDs unique within each role, and one shared identity and asset for Jadeja. Compare exact portal labels against the verified local list. Keep any live portal verification to a later authorized phase.
- Assert the hero figures, key counts, date range, two clean rebuilds, 160 comparison rows, 1,000 fixture resamples, role forecast metrics and weak 2026 auction replay against sources. Trace all 20 inclusion percentages, notes, pressure and ordinary rates, and numbers when opened. Check test counts are labelled as tests. Ensure positive, negative, zero and missing performance values are rendered accurately.
- Open all 19 assets in the generated preview. Check identity, appropriate credits and audience status. Run link and media checks. Check the build output only contains allowed derived aggregates, code and approved imagery. Exclude proprietary tables, delivery ledgers, unapproved media and user-specific filesystem paths. Check meaningful UI labels for conflicts introduced by minification or localization.

### Pass 2 · Review as an evaluator

- Inspect screenshot and live at `320 × 800`, `390 × 844`, `768 × 1024`, `1024 × 768` and `1440 × 900`. Capture the first screen, the two ranking sections, both Jadeja expanded cards, and the confidence and methodology visuals. Include a full-length desktop view and a representative mobile view. Test current Chromium and another available engine or browser. Record the actually tested environment.
- Give the first screen 10 seconds. Confirm the task, two leader picks, date and next action are immediately apparent. In one minute, find where the data came from, how pressure is defined, why a weaker pick is included and what 95.8% means. From a lower card, return straight to the role tabs and the methodology. Keep indentation and card densities consistent when subpanels open.
- Run keyboard and screen-reader or accessibility-tree checks, reset to reduced motion, disable motion initialization, click from and back to anchors, and test slow or failed media. Verify the landscape and mobile sticky nav, “Player evidence” controls, red/pink and blue contrast, source links, and chart text equivalents. Test performance at a representative throttled profile. Capture failures and fix the earliest responsible stage.
- Check credits and conditionals pass the intended review audience. Leave the local page presentable without requiring a login or external asset fetch. If stage-level exceptions remain, report them by player or affected component. Record a reproducible workaround only when it keeps facts and identity clear.

### Handoff

1. Return the project directory, install and local build/preview instructions, production build location, tests and outcomes, screenshots, what the user can click, and any specific pending item. Include the data snapshot date and exact list source.
2. Maintain a short release review file in the dashboard directory with the two pass results, visual checks, intended use of client data, media provenance status and available follow-up paths. The deliverable here is the local dashboard build. Any public deployment, Unstop upload or accompanying report creation requires a separate task.
3. If a real dependency prevents a complete final build, deliver the verified local sections and provide the exact next stage, action and evidence needed to finish. State the latest completed checks and the open check clearly.

### Loop and completion

Use a short defect list sorted by source data, image identity, interaction, accessibility, performance and visuals. Fix and rerun checks after each meaningful change. Repeat both acceptance passes after a material data, order, accessibility or layout repair. **Pass** when both passes succeed and the local preview presents all 20 ranked entries with the 19 correct photos, the complete sourced study, motion and reduced-motion behavior. If a new discrepancy appears, return to [Stage 00](00_evidence_contract.md) for ranking or evidence errors, [Stage 01](01_portrait_library.md) for image issues, [Stage 02](02_visual_system.md) or [Stage 03](03_rankings_and_player_evidence.md) for cards and layout, [Stage 04](04_methodology_and_project_story.md) for modelling explanation, or [Stage 05](05_motion_accessibility_performance.md) for interaction and performance. On passing, end the implementation loop and send the handoff.
